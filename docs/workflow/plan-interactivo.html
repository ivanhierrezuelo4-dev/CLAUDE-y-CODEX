Veredicto

Recomendado

Probar el plugin oficial con el seguimiento nativo. No hace falta un mod ni una app.

  • Claude Codecon el plugin codex@openai-codex para delegar y revisar.
  • Seguimientoclaude agents para las sesiones de Claude, /codex:status para los trabajos de Codex y /usage para tu cuota.
  • MemoriaUna bóveda de Obsidian usada como carpeta Markdown, con un AGENTS.md breve que leen Claude y Codex.

El plugin reutiliza tu sesión local de Codex, así que su uso cuenta contra el cupo de tu ChatGPT. Las cuotas de Claude y Codex no se suman.

Con tu plan Pro: Claude Code usa Opus 5.5 por defecto, que es lo que más rápido gasta la ventana de 5 h. Con opusplan Claude planifica con Opus y ejecuta con Sonnet.

  • OpcionalBarra de estado con la cuota de Claude y el esfuerzo (la nativa o ccstatusline). Informe semanal con ccusage.
  • OpcionalVentana siempre visible: una terminal con claude agents fijada con PowerToys (Win+Ctrl+T).
  • EvaluarAgent Usage Monitor (widget con las dos cuotas, v0.1.0). Antes hay que auditarlo.
  • DescartadoMod propio, ampliar Nexo, Vibe Kanban (en cierre), Claude Squad, trackers que leen credenciales y una base vectorial.

Qué estamos construyendo

No es una aplicación. Es un kit de oficina: unos pocos archivos que se copian en cualquier proyecto (Roblox, Pragmat o uno nuevo) para que Claude y Codex trabajen con las mismas reglas. Más adelante te daré un prompt para adaptarlo a cada proyecto.

1c

Capacidad y relevo

Simulación

Claude orquesta, así que conserva siempre una reserva para coordinar: ~5 % de la ventana de 5 h y ~3 % de la semanal. Hace falta porque incluso delegar a Codex pasa por un pequeño subagente de Claude: con un 0 % no podría ni delegar ni revisar. Mueve los controles.

Cómo funcionaría técnicamente (confirmado en la documentación, no instalado)
  • La barra de estado recibe rate_limits.five_hour.used_percentage, seven_day.used_percentage y resets_at. Está disponible en Pro y aparece tras la primera respuesta de la sesión.
  • El script de la barra guarda esas cifras. Un hook UserPromptSubmit las lee y solo escribe una línea para Claude cuando se cruza un umbral.
  • Hueco: Claude Code no ve el cupo de Codex. Se mira con /status en Codex o con un lector de account/rateLimits/read (por evaluar).
  • El % se actualiza en cada respuesta, y un turno grande puede saltar de 90 a 100. Por eso el traspaso se prepara antes de llegar a la reserva.
  • Si Claude no está disponible, hablas con Codex directamente: lee el mismo AGENTS.md y la misma bóveda, y retomas con codex resume o /codex:transfer.

Memoria con Obsidian

Una bóveda de Obsidian es una carpeta de archivos Markdown. Ningún modelo la recuerda por sí solo: cada tarea recupera lo que necesita. Se empieza por el nivel más simple.

Oficina/
  AGENTS.md              ← reglas breves, ambas IA
  General/Preferencias.md
  Proyectos/
    Hecho-de-Nada/  Indice · Estado · Identidad
                    Procedimiento · Decisiones
    Pragmat/        Indice · Estado · Procedimiento
                    Oferta.md → enlaza tu Excel
      Clientes/<cliente>/  ← nunca mezclar
    Roblox/         Indice · Estado · Diseno
                    Economia · Decisiones
    <Nuevo>/        Indice ← crece con uso
  Aprendizajes/       ← solo comprobado
  Archivo/            ← sustituido, fuera
                         de la búsqueda

Fuente canónica de cada dato

  • Precios de Pragmat: tu Excel. La nota enlaza y resume con la fecha.
  • Identidad de Hecho de Nada: Identidad.md, la misma versión que usa tu skill.
  • Economía de Roblox: Economia.md, o tu Excel si ya existe.

Nota importante: estado: borrador | aprobado | sustituido, fuente, actualizado y sustituido_por.

Valor en el tiempo

Qué entra

  • Decisiones aprobadas
  • Procedimientos que funcionaron
  • Soluciones reproducibles
  • Estado actual del proyecto

Qué se recupera

  • Índice del proyecto
  • Búsqueda de términos concretos
  • Notas o secciones completas
  • Se comprueban fecha y estado; se amplía si falta algo

Qué se actualiza

  • Al cerrar, el agente propone de 0 a 3 aprendizajes
  • Tú apruebas
  • Se edita la nota existente
  • La versión anterior pasa a «sustituido»

6b

Autoauditoría y ahorro real

Lo que fallaba en el primer plan y cómo se ahorra de verdad. Las herramientas de «ahorro» rinden mucho menos de lo que anuncian. Lo que más ahorra es no hacer el trabajo dos veces.

Correcciones al plan anterior

  • No tuve en cuenta que en Pro el modelo por defecto es Opus 5.5. Ahora Opus planifica y Sonnet ejecuta (opusplan).
  • No dije que delegar también gasta Claude. Por eso la reserva y el traspaso se preparan antes del límite.
  • El simulador mandaba demasiado a «Claude coordina». Ahora prima «Codex directo» cuando hay contrato.
  • Revisión adversarial solo con riesgo alto. Con riesgo medio basta una revisión corta y dirigida.
  • Usar medium en Sol era una hipótesis. El piloto compara low (por defecto) con medium.
  • Faltaba medir el «impuesto fijo» de cada mensaje: /context, /usage (desglose por skill, plugin o MCP) y claude plugin details.
  • Los artifacts sirven para entender, no ahorran tokens, y no se meten en el contexto de trabajo.

Palancas de ahorro, por impacto

  1. Dos depósitos. Lo que gasta muchos tokens (leer mucho código, ciclos de prueba, implementar) va a Codex, que tiene su propio cupo. Claude piensa y revisa.
  2. Modelo según la fase: opusplan; Haiku para tareas mecánicas.
  3. Sesiones limpias: /clear entre tareas y /compact con instrucciones.
  4. Impuesto fijo pequeño: AGENTS.md breve, pocos MCP activos.
  5. Memoria selectiva: índice, luego búsqueda, luego nota concreta.
  6. Sin bucles: 2 correcciones como máximo, review gate apagado, nada de ultra.

Piloto y pendientes

Piloto de 2 semanas

  1. Inventario de solo lectura en tu PC: sistema operativo, versiones, modelos visibles y /codex:setup. No se leen secretos.
  2. Referencia: 2 o 3 tareas hechas como hasta ahora.
  3. 8–10 tareas: 2 de Pragmat, 2 de Roblox, 2 de Hecho de Nada (Claude solo), 1 bug y 1 proyecto nuevo.
  4. Por tarea se mide: tiempo total, intervenciones tuyas, correcciones, pruebas ejecutadas y % de cuota antes y después.
  5. Prueba de memoria: una respuesta conocida, una nota sustituida y una nota de otro proyecto.
  6. Se adopta solo si se cumplen los requisitos y las pruebas, sin fallos críticos. Si baja el consumo pero aumenta el retrabajo, no se adopta.

Son metas del piloto, no resultados. No hay ningún porcentaje de ahorro demostrado.

Se comprueba en tu PC

  • Sistema operativo. Supuesto: Windows
  • Claude Code ≥ 2.1.139 (agent view) y Codex ≥ 0.153 (modelos 6.x)
  • Plan de Claude y modelos visibles en /model
  • Límites de Codex en tu ChatGPT Plus (la web oficial estaba bloqueada desde aquí)
  • Codex en Windows nativo o WSL
  • Roblox Studio/MCP y Buffer: inspeccionar, no reconstruir
  • Dónde están tus MD y Excel
Primer paso: Claude Code hace el inventario e instala el plugin. Tú solo inicias sesión en Codex en la ventana oficial cuando aparezca.
